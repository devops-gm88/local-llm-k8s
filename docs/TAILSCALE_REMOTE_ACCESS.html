Reach the LLM Node From Any Network

Set up Tailscale on the second Mac. Publish the gateway to your devices only. Operate it from this Mac.

1. What this does

Tailscale makes a private network. It is called a tailnet. Each device gets a private address in 100.64.0.0/10.

Tailscale finds a path between the devices. The devices can be on different Wi-Fi networks. You do not open a port on a router.

This guide uses two Macs:

  • Node Mac — the older Intel Mac. It runs the cluster. It stays on.
  • Work Mac — the Apple silicon Mac. You use it to work.

After this setup, your phone and your Work Mac can call the model from any network. Only devices in your tailnet can do this. The service is not on the public internet.

2. Before you start

  • Both Macs use the same Tailscale account. You already have the account on the Work Mac.
  • The cluster runs on the Node Mac. See docs/RESTART_CHEATSHEET.html.
  • The Node Mac has Admin rights for your user.
  • You can open the Tailscale admin console. You need this for 3 settings.

First

The repository on this day is for arm64 Macs only. It has arch: aarch64, an arm64 VM image, and arm64 tools.

Change the repository for Intel first. Then run make up on the Node Mac. The changes are: host CPU detection, vmType: qemu on older macOS, and an amd64 nerdctl bundle. This is a separate task.

3. Install Tailscale on the Node Mac

1

Open the download page.

On the Node Mac, open this page in a browser:

https://tailscale.com/download/mac
2

Download the standalone package.

Select the standalone download. Do not select the App Store version. The standalone package includes the command line.

The Tailscale app is a universal program. It runs on Intel and on Apple silicon.

3

Install the package.

Open the file. Follow the steps on the screen. The installer asks for your password.

4

Check the command line tool.

Open Terminal on the Node Mac. Run this command:

tailscale version

The command must show a version number. If Terminal shows "command not found", close Terminal and open it again.

4. Join the Node Mac to your tailnet

1

Start Tailscale and set the name.

tailscale up --hostname=intel-mac

Use the name intel-mac in this guide. You can use a different name. If you do, change the name in the commands below.

2

Sign in.

The command prints a web address. Open the address on any device. Sign in with the same account as the Work Mac.

3

Check the machine in the admin console.

Open https://login.tailscale.com/admin/machines. Find intel-mac. The state must be Connected.

4

Disable key expiry for this machine.

Open the menu of intel-mac. Select Disable key expiry.

A server must not lose its key when you are away. Do not do this for a laptop that you carry.

5

Read the private address and the name.

tailscale ip -4
tailscale status

The first command gives an address that starts with 100.. The second command gives the name intel-mac.<your-tailnet>.ts.net.

Write down <your-tailnet>. You need it below.

5. Check the path from the Work Mac

1

Look for the Node Mac.

tailscale status

Find the line intel-mac. It must not show offline.

2

Test the private network.

tailscale ping intel-mac

You must see replies. The first reply can take 10 seconds. A direct path can show later. Do not stop the test.

3

Turn on SSH on the Node Mac.

On the Node Mac, open System Settings. Open General. Open Sharing. Turn on Remote Login.

Add your user in the list of allowed users.

4

Test SSH from the Work Mac.

ssh <you>@intel-mac 'hostname'

The command must print the name of the Node Mac. Replace <you> with your macOS user name.

6. Publish the gateway to your tailnet only

The cluster answers on port 30080 of the Node Mac. The command serve publishes this port to your tailnet. It does not publish it to the internet.

1

Check the cluster on the Node Mac.

curl -s http://127.0.0.1:30080/readyz

The answer must include "status":"ready". If the answer is an error, run make up in the project folder first.

2

Publish the port.

tailscale serve --bg 30080

The command makes an HTTPS address for your tailnet.

The option --bg runs the service in the background. The service stays after you close the terminal window.

3

If you get an HTTPS error.

Open the admin console. Open DNS. Turn on HTTPS Certificates. Run the command again.

If you cannot turn on HTTPS, use HTTP on your tailnet instead:

tailscale serve --bg --http=80 30080
4

Read the public name.

tailscale serve status

The command prints the address, for example https://intel-mac.<your-tailnet>.ts.net.

5

Test from the Work Mac.

curl -s https://intel-mac.<your-tailnet>.ts.net/readyz

The answer must include "status":"ready".

7. Call the model from any device

The gateway asks for a token. The token is a secret word. It is in a file on the Node Mac.

1

Read the token on the Node Mac.

cat ~/Workspace/local-llm-k8s/.kube/gateway-token

Put the token in a password manager. Do not send it in a chat or an email.

2

Send one question from the Work Mac, the phone, or a tablet.

TOKEN="<paste the token>"
curl -s "https://intel-mac.<your-tailnet>.ts.net/ask" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"question":"What is the capital of Canada?","max_tokens":64}'

Read the field answer in the reply.

3

Read the health without a token.

The paths /healthz and /readyz do not use the token. Use them to check the node from any device.

8. Operate the cluster from the Work Mac

1

Open a tunnel to the cluster API.

ssh -N -L 6443:127.0.0.1:6443 <you>@intel-mac

Keep this window open. The tunnel sends port 6443 from the Node Mac to this Mac.

Why a tunnel: the k3s certificate is valid for 127.0.0.1. A direct call to the tailnet address fails the certificate check.

2

Copy the kubeconfig to the Work Mac.

ssh <you>@intel-mac 'cat ~/Workspace/local-llm-k8s/.kube/config' > ~/.kube/intel-k3s.yaml
3

Use the remote cluster.

export KUBECONFIG=~/.kube/intel-k3s.yaml
kubectl get nodes

One line must show Ready. If two clusters run at the same time, the tunnel and this variable select the Node Mac.

4

Deploy a change.

ssh <you>@intel-mac 'cd ~/Workspace/local-llm-k8s && git pull && make deploy'

Deploy from git. Do not copy files by hand. The remote node must match the committed repository.

5

Use the gateway from this Mac.

Open a second tunnel for the gateway port:

ssh -N -L 30080:127.0.0.1:30080 <you>@intel-mac

Then use make demo in a second terminal. make demo finds 127.0.0.1:30080.

Benchmark

Do not quote benchmark numbers that you collect through the tunnel. The tunnel is in the path. Run make bench on the Node Mac itself. Then copy bench/results.json to the Work Mac.

9. Keep the Node Mac running

1

Stop sleep.

Open System Settings. Open Lock Screen. Set the display to turn off only when you want. Set sleep to Never when the Mac has power.

On a desktop Mac, also turn on Prevent automatic sleeping when the display is off.

2

Keep the Mac awake while you are away.

caffeinate -s

Keep this window open. The command stops when you close the window or press Control and C.

3

Turn on automatic login.

Open System Settings. Open Users & Groups. Turn on Automatic login.

This step helps after a power cut. Tailscale and the Tailscale app start only after a user logs in.

4

Start the cluster after a reboot.

The cluster does not start by itself. Run make up in the project folder on the Node Mac.

The appendix below starts it automatically at login.

5

Test a full restart.

Restart the Node Mac. Wait 3 minutes. From the Work Mac, run tailscale ping intel-mac and the /readyz request. Both must work.

10. Rules

  1. Use serve. Do not use funnel. funnel puts the service on the public internet.
  2. Do not open a port on the router. Tailscale does not need it.
  3. Keep the gateway token secret. Give it only to people that must use the model.
  4. In the admin console, open Access Controls. Make sure only your devices can reach intel-mac.
  5. If a device is lost, remove it from the admin console. The device loses all access.
  6. Do not put the Node Mac on a network that you do not trust without a password. Tailscale encrypts the traffic, but the Mac is still a machine on that network.

11. Problems and actions

You seeCauseAction
intel-mac shows offline The Mac is asleep or has no network. Wake the Mac. Check the sleep settings in section 9. Check the Wi-Fi or the cable.
tailscale ping intel-mac fails The devices use different accounts, or one device is not signed in. Run tailscale status on both Macs. Run tailscale up again on the Node Mac.
/readyz fails through the served address The cluster is not running. On the Node Mac, run curl -s http://127.0.0.1:30080/readyz. If this fails, run make up.
An error about HTTPS certificates HTTPS is off for the tailnet. Admin console, DNS, turn on HTTPS Certificates. Run tailscale serve --bg 30080 again.
tailscale serve gives no URL The command did not stay in the background. Run tailscale serve status. If the list is empty, run tailscale serve --bg 30080 again.
kubectl cannot connect The SSH tunnel is closed. Open the tunnel again. Keep the window open.
kubectl shows a certificate error The kubeconfig points at the tailnet address. Use 127.0.0.1 with the tunnel. Do not put the tailnet address in the kubeconfig.
/ask gives 401 The token is missing or wrong. Read the token again on the Node Mac. Check the header Authorization: Bearer <token>.
SSH asks for a password Remote Login is off, or your user is not in the list. Turn on Remote Login. Add your user.
Tailscale is offline after a restart The app does not start at login. Turn on automatic login. Open the Tailscale app. Turn on Start on login.

12. Final check

  • tailscale status shows intel-mac as connected.
  • tailscale ping intel-mac works from the Work Mac.
  • ssh <you>@intel-mac 'hostname' works.
  • curl https://intel-mac.<your-tailnet>.ts.net/readyz shows ready.
  • /ask returns an answer from the phone or the Work Mac.
  • kubectl get nodes works through the tunnel.
  • The Node Mac does not sleep.
  • Key expiry is off for intel-mac.
  • tailscale funnel status shows no public service.

Appendix: start the cluster at login

This step is optional. It makes the cluster start after a reboot.

1

Create the file.

mkdir -p ~/Library/LaunchAgents
cat > ~/Library/LaunchAgents/com.local.llmk8s.up.plist <<'PLIST'
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <key>Label</key><string>com.local.llmk8s.up</string>
  <key>RunAtLoad</key><true/>
  <key>WorkingDirectory</key><string>/Users/<you>/Workspace/local-llm-k8s</string>
  <key>ProgramArguments</key>
  <array>
    <string>/bin/bash</string>
    <string>-lc</string>
    <string>sleep 60 && make up</string>
  </array>
  <key>StandardOutPath</key><string>/tmp/llmk8s-up.log</string>
  <key>StandardErrorPath</key><string>/tmp/llmk8s-up.err</string>
</dict>
</plist>
PLIST

Replace <you> with your user name. The command waits 60 seconds for the network.

2

Load the file.

launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.local.llmk8s.up.plist
3

Read the log.

cat /tmp/llmk8s-up.log

If the log shows an error, run make up by hand. Then read docs/RESTART_CHEATSHEET.html.
