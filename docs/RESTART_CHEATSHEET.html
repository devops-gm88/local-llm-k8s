Restart the Local LLM Cluster

Short steps. Easy words. Keep this page near the Mac.

1. What this is

This project puts a small language model on a cluster. The cluster runs inside a virtual machine (VM) on the Mac.

A gateway answers each question. A gateway is a small web service. It sends the question to the model server. The model server is called Ollama.

You do not need Docker, a cloud account, or a GPU.

2. What you need

  • Apple silicon Mac with 16 GB RAM.
  • 15 GB free disk space.
  • An internet connection for the first start.
  • About 2 minutes for a normal start.
  • About 15 minutes after you delete the VM.

3. Start the cluster

1

Open Terminal.

2

Go to the project folder.

cd ~/Workspace/local-llm-k8s
3

Start the VM and the cluster.

make up

Wait for the table of pods. A pod is one running container in the cluster.

This command does five things:

  1. It starts the VM.
  2. It installs Kubernetes in the VM. The cluster software is called k3s.
  3. It builds the gateway image.
  4. It downloads the model. The model is qwen2.5:0.5b-instruct.
  5. It starts the gateway and the model server.
4

Check the node.

Kubernetes calls each machine a node. Run this command:

kubectl get nodes

One line must show Ready.

4. Use the cluster

Ask one question

make demo

The gateway shows the answer, the token counts, and the time.

Run the benchmark

make bench

The command writes three files: bench/results.json, bench/results.csv, and the charts in bench/charts/.

Make the cost table

make cost

The command writes cost/break_even.csv and cost/break_even.png.

5. Stop the cluster

1

Delete the work.

make down

The model files stay on the disk of the VM. The next start is therefore fast.

2

Stop the VM.

make stop

This step frees 6 GB of RAM for macOS.

6. Problems and actions

You seeCauseAction
kubectl cannot connect The VM is stopped. Run make up.
SSH does not open after make up A known Ubuntu 26.04 problem. Lima shows "Running", but the network is not ready. Read section 7.
Pod state ImagePullBackOff The gateway image is not in the cluster. Run ./scripts/build_gateway.sh. Then run make up.
CrashLoopBackOff and the log shows "Permission denied: /app/app.py" The image has a wrong file mode. Run make up to build the image again.
/readyz gives 503 with model_missing The model download is not complete. Wait 5 minutes. Then run make demo again.
Pod state OOMKilled The model is too large for the memory limit. Use qwen2.5:0.5b-instruct. Do not use a larger model on this Mac.
The autoscaler shows cpu: <unknown> The metrics service is not ready. Wait 60 seconds.
make bench stops with "Server disconnected" A pod restarted during the run. Run make bench again.

7. If SSH does not open

Lima can show "Running", but the VM does not accept SSH. This is a known problem on Ubuntu 26.04.

The file scripts/lima/llmk8s.yaml.in has the correct setting. Do not remove this line:

param:
  internal_netplanOptional: "true"
1

Read the log of the VM.

tail -20 .lima/llmk8s/ha.stderr.log

If you see "Waiting for port to become available" again and again, do step 2.

2

Delete the VM and start again.

./scripts/destroy.sh
make up

The command asks a question. Type y and press Enter.

9. Rules

  1. Do not spend money. Use no cloud service and no API credit.
  2. Do not make the VM larger than 6 GB RAM. macOS needs the other 8 GB.
  3. Do not use a model larger than 0.5B on this Mac. The model must fit in the memory limit.
  4. Do not claim a GPU result. This cluster has no GPU. The cost model uses an assumed GPU speed.
  5. Do not change the manifests without a benchmark run. The README numbers must match the committed JSON.
